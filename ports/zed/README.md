# LiG for Zed

Zed is an editor port: the adapter covers editor chrome, syntax, diagnostics, Git states, player selections and the integrated terminal. It shares the same `core/spec.json` and style intent as Neovim and VS Code. This is the independent [zed-theme-LiG distribution repository](https://github.com/0froq/zed-theme-LiG), generated by [LiG](https://github.com/0froq/lig). The initial release is a preview; it is not yet listed in the Zed extension store.

## Install

Clone the repository, optionally pinned to the first release:

```sh
git clone --branch v0.1.0 https://github.com/0froq/zed-theme-LiG.git
```

In Zed run `zed: install dev extension` and select the cloned directory containing `extension.toml`. Then use `theme selector: toggle` to choose **LiG Light**, **LiG Dark**, **LiG Light Paper** or **LiG Dark Paper**. The repository contains only a theme extension; no language server or executable code is included. Zed documents this workflow in [Developing Extensions](https://zed.dev/docs/extensions/developing-extensions).

Alternatively, download `lig-zed-extension.zip` from this repository's [releases](https://github.com/0froq/zed-theme-LiG/releases), extract it and select that directory. Install only one copy of the extension.

### Local theme files

For a file-only installation, use the JSON files in `themes/`, or download a single `lig-light.json`, `lig-dark.json`, `lig-light-paper.json` or `lig-dark-paper.json` from the LiG site. The site's `lig-zed-all.zip` contains all four local-theme files, rather than the extension package.

Copy the JSON files into `~/.config/zed/themes/` on macOS/Linux, or `%USERPROFILE%\AppData\Roaming\Zed\themes\` on Windows. Keep filenames distinct, then reload Zed and use `theme selector: toggle` to choose **LiG Light**, **LiG Dark**, **LiG Light Paper** or **LiG Dark Paper**.

Optional system appearance switching in Zed's existing settings:

```json
{
  "theme": {
    "mode": "system",
    "light": "LiG Light Paper",
    "dark": "LiG Dark Paper"
  }
}
```

Merge only the theme selection after approval; keep other settings. Back up conflicting files first. Remove the added theme files and restore the previous `theme` value to roll back.

### Update and rollback

For a repository installation, fetch tags and check out the chosen release, then reload the dev extension in Zed. To roll back, check out the previous tag and reload. To uninstall, remove the dev extension through Zed's Extensions page and restore your previous theme setting. For local files, replace only LiG's JSON files after backing them up; remove them to uninstall. Do not install both the extension and local copies with the same theme names.

## Source and reproducibility

Do not edit generated themes here. Change the palette or adapter in [LiG's source snapshot](https://github.com/0froq/lig/tree/zed-port-2026-10-11), then run `pnpm ports:generate` there. `dist/ports/zed-extension/` contains this repository payload and `lig-zed-extension.zip`. Publish a new repository commit and release when updating the generated output.

`lig-build.json` records the source ref, compiler/design versions, exact input SHA-256 and checksums for every payload file. Website local themes and repository themes are checked for byte equality. Distribution is static; installing it does not fetch tokens or require Node.js.

## Scope and verification

The adapter emits Zed's [v0.2.0 theme format](https://zed.dev/docs/extensions/themes). Local paths and selection follow [Zed's theme documentation](https://zed.dev/docs/themes#local-themes). It does not install languages, modify capture queries, enable semantic tokens, change fonts/keybindings or configure external tools.

Zed's native capture names are mapped explicitly to LiG's shared roles. Language queries and optional semantic tokens can classify the same code differently from Neovim/VS Code. The theme format cannot express every shared style modifier (for example link underlines); supported foreground, italic and weight intent is preserved. Dim terminal slots reuse the normal ANSI colors; bright slots retain the shared emphasis colors.

Data checks validate token provenance, all 16 ANSI slots, appearance metadata, artifact checksums and ZIP contents. They do not establish native visual acceptance. Manually check all four variants in Zed: editor text and syntax, selections/cursor, completion menus, panels/tabs, diagnostics/Git colors and ANSI output. Zed settings or theme overrides may take precedence.
